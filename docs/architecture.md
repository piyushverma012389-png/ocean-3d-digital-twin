# System Architecture — SIH26067
## Web-based Interactive 3D Visualization Platform Integrating Numerical Ocean Model Outputs and In-Situ Observations

### 1. Architectural Philosophy & Overview
SIH26067 addresses the challenge of visualizing high-dimensional, multi-source oceanographic datasets across the Indian Ocean basin (25°S to 30°N, 30°E to 115°E). The platform bridges two fundamentally different data paradigms:
1. **Eulerian Gridded Model Outputs**: Continuous 4D hydrodynamic fields ($x, y, z, t$) generated by ocean circulation models such as ROMS (Regional Ocean Modeling System), INCOIS MOM (Modular Ocean Model), HYCOM, or NEMO.
2. **Lagrangian In-Situ Observations**: Point-wise and vertical trajectory profiles collected by autonomous Argo floats, underwater gliders, drifters, and moored ocean buoys.

To achieve fluid, 60-FPS interactive 3D rendering in standard web browsers without overburdening client GPUs or overwhelming bandwidth, the platform uses a decoupled, multi-tier architecture.

### 2. Key Modules & Separation of Concerns

#### 2.1 Frontend Modular Architecture (`frontend/src/`)
- **`OceanViewer`**: Canvas root mounting camera, scene lighting (directional sunlight with oceanic depth attenuation), fog, and coordinates raycaster.
- **`BathymetryMesh`**: Custom 3D plane displaced vertically using Indian Ocean bathymetric elevations. It visually depicts the shelf breaks, mid-ocean ridges (Ninety East Ridge, Central Indian Ridge), and trenches (Java Trench).
- **`OceanSurfaceLayer`**: 3D horizontal slice positioned dynamically at the active depth level ($z$). Colors are rendered using high-resolution scientific colormaps (Turbo, Viridis, Thermal, Haline).
- **`CurrentVectors`**: Uses `THREE.InstancedMesh` to render hundreds of 3D flow vector arrows representing velocity components $(u, v)$ with zero per-object draw call overhead.
- **`ObservationLayer`**:
  - Renders Argo floats as surface markers with translucent vertical lines extending down to their maximum parking/profile depth (up to 2000m) with sensor sample nodes.
  - Renders underwater gliders with 3D sawtooth trajectories mapping mission waypoints.
  - Supports interactive pointer picking; clicking an in-situ asset triggers the comparison module.
- **`ComparisonPanel`**: Side-by-side scientific profile evaluation displaying numerical model forecast versus in-situ CTD measurements with depth-dependent bias and RMSE.
- **`ColorLegend`**: Colormap bar displaying physical range, units ($^{\circ}\text{C}$, $\text{PSU}$, $\text{m/s}$, $\text{m}$), and palette presets.
- **`DataPanel`**: Floating telemetry HUD showing cursor coordinates, active layer toggles, and metadata.
- **`OceanControls`**: Camera preset jumps: Indian Ocean Basin, Arabian Sea, Bay of Bengal, Equatorial Trench, 3D Isometric, and Top-Down Orthogonal.

#### 2.2 Backend Architecture (`backend/app/`)
- **`core/config.py`**: Centralized domain configuration (geographic bounds, standard depth levels, variable definitions, and unit scales).
- **`models/schemas.py`**: Pydantic schemas enforcing strict contracts for coordinate grids, metadata, observations, and statistical profiles.
- **`services/model_service.py`**: Manages model ingestion and 4D extraction. It decodes $(lon, lat, depth, time)$ requests, extracts the sub-grid, and formats response buffers.
- **`services/observation_service.py`**: Manages active Argo floats and glider missions, providing metadata, profile records, and quality control flags.
- **`services/bathymetry_service.py`**: Computes elevation and depth matrix for the Indian Ocean basin with land-sea masking.
- **`services/comparison_service.py`**: Performs spatial-temporal collocation between model grid cells and observation coordinates, deriving difference metrics.

### 3. Coordinate System & Projection Strategy
1. **Geographic Coordinates**: Input datasets use standard WGS84 coordinates:
   - Longitude: $30^{\circ}\text{E}$ to $115^{\circ}\text{E}$
   - Latitude: $-25^{\circ}\text{S}$ to $30^{\circ}\text{N}$
   - Depth: $0\text{ m}$ (surface) to $-4000\text{ m}$ (abyssal plains)
2. **Three.js World Coordinates**:
   - Longitude maps to World X: $[-10, 10]$
   - Latitude maps to World Z: $[-7, 7]$
   - Depth maps to World Y: $[0, -3.5]$ (scaled with vertical exaggeration for oceanographic insight)
3. **Raycasting**: The mouse pointer in screen space is back-projected through the camera frustum onto the horizontal slice or seabed mesh to compute real-time geographic latitude, longitude, and depth.

---

### 4. Performance & Scalability Strategy
- **Instanced Mesh Rendering**: Vector arrows and Argo buoys are rendered via `THREE.InstancedMesh`, condensing thousands of geometries into single draw calls.
- **Texture-Driven Scalar Fields**: Ocean slice variables are mapped directly via GPU data textures, enabling smooth gradient interpolation without vertex bloat.
- **Progressive LOD & Caching**: Slices and bathymetric grids are pre-sampled or cached in memory; client requests specify decimation factors when zoomed out.
